# CybergateFX

A Django web app that lets users browse forex mentors, book mentorship
sessions, and (for signal subscribers) view a live trading-signal feed.

This is a university assignment — the code is intentionally simple, well
commented, and uses the kind of patterns you'd see in a real fintech
startup's first MVP.

---

## Features

- Sign up / log in by email (custom user model)
- Browse mentorship plans (1-on-1 Coaching / Group / Signal Subscription)
- Browse mentors and book a time slot
- Simulated payment on booking (clearly labelled as simulated)
- Customer dashboard — upcoming / past bookings, cancel bookings
- Live signal feed — visible only to active Signal Subscribers
- Django admin with a custom dashboard, list_editable, inlines, and
  the ability to post Signals directly

## Local setup

```bash
# 1. create and activate a virtualenv
python -m venv .venv
source .venv/bin/activate          # macOS / Linux
# .venv\Scripts\activate           # Windows

# 2. install dependencies
pip install -r requirements.txt

# 3. apply migrations
python manage.py migrate

# 4. seed demo content (admin, demo user, 3 mentors, 3 plans, slots, signals)
python manage.py seed

# 5. run the dev server
python manage.py runserver
```

Open http://127.0.0.1:8000/ to see the site.

|------------|--------------------|--------------------------|
| Mon–Fri    | 09:00 – 17:00      | one slot per hour (1h)   |

## Environment variables

`settings.py` reads the following from environment variables — never
hardcoded — so the app can be deployed cleanly:

| Variable        | Default (local)                | Production example                  |
|-----------------|--------------------------------|-------------------------------------|
| `SECRET_KEY`    | insecure dev key               | long random string                  |
| `DEBUG`         | `True`                         | `False`                             |
| `ALLOWED_HOSTS` | `*`                            | `cybergatefx.onrender.com`          |
| `DATABASE_URL`  | `sqlite:///db.sqlite3`         | `postgres://user:pass@host/db`      |

`dj-database-url` parses `DATABASE_URL` so the same `settings.py` works
on a free Render dyno without modification.

## Deployment (Render / Heroku-style)

```bash
# Render build command:
pip install -r requirements.txt && python manage.py collectstatic --noinput && python manage.py migrate

# Render start command:
gunicorn cybergatefx.wsgi:application
```

Set the four env vars above in the dashboard.

## Notes on what's intentionally *not* here

- No Celery / Redis — `seed` is synchronous, payments are simulated.
- No real payment gateway — `Payment.mark_paid()` flips status to PAID.
- No real-time price feed — signals are posted by mentors via admin.

The brief was clarity over cleverness.
